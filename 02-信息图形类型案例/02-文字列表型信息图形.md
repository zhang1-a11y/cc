# 文字型／列表型信息图形（Informational / List Infographics）

> 来源：PDF 第 23 页；类型名称已核对，具体画面待核验。见[该页记录](PDF对照与案例索引.md#list)。

## 定义与边界

以标题、短解释、关键词、条目和必要符号作为主要载体，通过信息层级、分组和阅读路径形成图形化表达。Informational 可以围绕概念或问题展开说明，不一定是列表；List 强调重复的条目结构。统计图不是必需条件，装饰图标也不自动使一篇长文成为信息图形。

先区分并列知识、操作步骤、优先级排名、检查清单和检索目录。它们可以外观相似，但数据关系、序号含义与叙事方式不同。

## A 基本的数据逻辑

条目表至少有 `item_id、title、body、category、order_key、source`。依用途增加：步骤的前置条件与输出、排名的依据与值、清单的状态、索引的字符键。并列条目不随意补上依赖关系。

涉及共同属性分组时使用[编目逻辑](../01-信息图形数据逻辑/03-编目型信息图形概念定义.md)，父子嵌套使用[层级逻辑](../01-信息图形数据逻辑/02-层级型信息图形概念定义.md)，按字符组织使用[字母表逻辑](../01-信息图形数据逻辑/04-字母表型信息图形概念定义.md)。同一列表可有主逻辑与辅助逻辑。

## B 统计图形与计算方式

基础形式为列表、卡片、分类索引或解释模块。可以只有关系组织，没有统计计算；此时如实注明“不涉及数值统计”，不为满足 B 项强加图表。

若统计项目数、类别频数或完成率，先定义对象单位与去重规则。完成率 = 已完成的适用项目数／全部适用项目数，注明如何处理“不适用”；排名必须说明比较指标、方向、并列与筛选范围。“十大”若为编辑选择，应标明选取原则，不能暗示统计前十。

## C 视觉编码

| 元素 | 可编码内容 | 视觉优化 |
| --- | --- | --- |
| 点／勾选框 | 条目、状态 | 统一位置与状态词，避免只靠颜色 |
| 线／箭头 | 分隔、依赖、操作方向 | 分隔线与流程线分开；并列项不用箭头伪造因果 |
| 面／留白 | 分组、模块边界 | 重复网格、对齐和稳定间距 |
| 体／插画 | 对象或使用情境 | 服务理解，不遮挡正文或伪装为量值 |
| 符号 | 类别、动作或状态 | 一种含义固定一种图标，配短标签 |
| 色彩 | 类别、重点、状态 | 配合形状与文本；跨条目语义一致 |
| 字号／字重／序号 | 标题层级、阅读入口、编号 | 区分编号、步骤与排名，正文保持可读 |

每项使用同一字段顺序和语法粒度。关键解释不可一概压缩成图标；必要正文、图例与来源应保留。

## D 数据／信息架构

先给主题、使用对象、范围与排序规则，再按任务或类别分组，最后展开条目。每项可采用“标题 → 一句要点 → 条件／证据 → 来源”。文字解释型可采用“问题 → 定义 → 关键事实 → 例外”，不强制编号。

索引与详情分开，新增条目沿用稳定 ID；缺失字段写未知。长列表提供组标题和定位入口，跨页保留续接提示。

## E 视觉叙事架构

并列列表允许跳读，用重复结构降低查找成本；步骤列表强调起点、依赖、完成条件；排名列表交代比较依据；概念说明强调从问题到解释。不能用同一条蛇形箭头套用所有内容。

按照 PDF 第 40、42、69 页的方法，检查读者能否辨认主题、找到目标条目、理解强调内容并区分事实与评论。未实际做阅读测试时，只能写评估建议，不声称已有“三秒找到”等实验结果。
