# 文字型／列表型信息图形（Informational / List Infographics）

> 证据状态：当前为方法框架，尚无本主题案例原图可供逐图验证。

## 定义与边界

以标题、序号、条目、短解释和符号构成主要信息载体，图表可以缺席。信息图形的“图”体现在可视化的信息层级、分组、路径与符号编码，不取决于是否出现统计图。列表可承载步骤、建议、清单、类型或问答；需要区分有序流程、按优先级排序和可自由浏览的并列项目。纯长篇文章加几个装饰图标，不自动成为有效的信息图形。

## 数据逻辑与计算

基础数据是条目表：ID、标题、内容、类别、排序键、优先级、图标、来源；步骤另有依赖或先后字段，清单另有状态字段。项目数、类别频数、完成比例可以统计，但应说明单位与分母；“十大”必须交代筛选与排序依据，否则只是编辑选取。若内容采用编目或字母索引，可关联[编目逻辑](../01-信息图形数据逻辑/03-编目型信息图形概念定义.md)与[字母表逻辑](../01-信息图形数据逻辑/04-字母表型信息图形概念定义.md)；有父子嵌套时关联[层级逻辑](../01-信息图形数据逻辑/02-层级型信息图形概念定义.md)。

## 视觉编码

数字序号编码先后，不应给并列项目添加虚假的排名。点与勾选框标识项目／状态，线或箭头只在有依赖时表示流程，色块与留白组成组，象形符号帮助扫读类别。重点信息用字号、字重和对比突出，正文行长、行距和重复网格保障连续阅读；图标在所有条目中语义一致。装饰性 3D 插画可为入口提供情境，但不能遮住正文。色彩不是唯一状态标记，关键状态配文字或形状。

## 信息架构与叙事

开头交代“适用于谁、何时、包含哪些内容”，随后按决策任务或使用顺序分组，再到条目层的“动作／定义 → 简短解释 → 证据或例外”。并列列表允许跳读；步骤列表须提供起点、方向与完成条件。编号与段落层级保持稳定，跨页列表保留续页提示，末尾给出处、修订时间及适用边界。

## 逐图分析时记录

1. 该图实际是操作顺序、排序推荐、分类目录还是并列事实？
2. 第一眼的标题与下一层入口是否明确，能否 3 秒扫到目标条目？
3. 图标是在编码类别／状态，还是仅装饰？颜色是否跨项稳定？
4. 条目是否同粒度、同语法？哪些文字不可删，哪些可由符号代替？
5. 数字是否暗示证据、排名或计数，依据是否可核对？
