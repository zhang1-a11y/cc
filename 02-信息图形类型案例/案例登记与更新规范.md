# 案例登记与文档更新规范

## 目录边界

沿用现有 01、02 文件夹，不创建其他文件夹或子文件夹。01 固定保留五篇数据逻辑定义，只保存文字与案例文本链接；02 平铺三篇表现类型说明、索引、规范、模板及后续具体案例记录与图片。

新案例建议使用稳定文件名“C001-作品简称.md”，原图如需保存使用同目录“C001-原图.png”。不使用“每个案例一个文件夹”的方式。

## 来源与记录单位

用户 PDF 页码按文件实际页序从 1 开始，不与画面内的页码混用。已有课件来源登记在[PDF 对照与案例索引](PDF对照与案例索引.md)。一页有多件作品时分别记录；同一作品跨页时使用同一案例 ID 并列出页码，不重复统计。

记录原始作品名、作者、日期、出处、原图或来源路径、图像版本与使用状态；未知即写未知。课件署名与已经核验的原作归属分别标注。不把章节标题当成作品名，不凭图片排版猜测作者和具体数值。原始 PDF 不因被用于分析而自动公开上传到仓库。

## 证据等级

| 等级 | 可写内容 | 不可混淆 |
| --- | --- | --- |
| 课件明示／来源明示 | 可核对的原文分类、署名与说明 | 不等于已看清作品画面 |
| 直接观察 | 实际看清的元素、位置、文字、数值与图例 | 明确画面区域与清晰度 |
| 分析推断 | 根据观察解释数据关系与阅读路径 | 写明理由和替代解释 |
| 方法建议 | 面向该任务的改进办法 | 不说成原作者已采用 |
| 待核实 | 无法辨认的数值、作者、比例、出处等 | 不用常见做法补空白 |

仅完成文字抽取或页码登记的项目，不标“逐图分析完成”。结论需能回到具体作品、页码和画面区域。

## 按 A—E 分析

1. **A 数据逻辑**：识别对象、字段、粒度、时间／分类／层级／字符／空间关系，标明主逻辑与辅助逻辑。
2. **B 统计图形与计算**：记录实际图形、单位、分母、计算与比例尺；无统计就如实说明，未知则待核实。不能从视觉大小直接反推量值。
3. **C 视觉编码**：逐项记录点、线、面、体、符号、色彩、文字分别代表什么，区分定量映射、语义指代、分组和装饰。
4. **D 数据／信息架构**：区分数据表关系与版面信息层级，记录概览、分组、详情、图例、来源和导航。
5. **E 视觉叙事架构**：描述真实可见的入口、阅读顺序、强调、转折与收束，区分作者编排意图与经过测试的读者行为。

依据课件第 43 页，先清洗与建结构，再分析编码、版式和内容关联；依据第 40、69—70 页，结合读者任务采用概要到细节的结构。课件原理只是方法依据，案例结论仍需图像证据。

## 每次新增或纠错的同批更新

1. 在 02 新增或修订具体记录及原图／来源，填齐证据和未知项。
2. 更新 02 的相关类型文档与索引，写出该案例支持、限制或反驳哪一条原则。
3. 更新 01 对应 A—E，把旧假设改成有适用条件的方法，并加入具体案例的文本链接。
4. 更新修订日期与变更记录，写明理由；保持案例 ID、文件名和既有链接稳定。
5. 检查目录未增加，01 无图片／图片嵌入，链接与锚点可达，术语和统计口径一致。

这五步在同一次案例提交中完成；不能只增加图片而不更新方法。没有影响的方法文档可注明“已核对，原则未变”，不为凑更新而改写。

## 原则提炼与反例

原则附支持案例、观察位置、适用范围及反例。单例只能支持该情境下的观察，不足以声称通用规律。新案例冲突时，先核对数据单位、任务、受众与图形编码，再决定限定或替换原则。

ISOTYPE、普通图标与 ISO 公共标识分开登记；图像数量计量、符号面积计量和符号装饰分开判断。时间轴顺序与真实时距、层级与等级、编目与字母序也分别检查。

## 评估与完成状态

参考课件第 42 页检查主题、参数、强调、事实与评论；参考第 48—55、64—71 页检查清晰度、密度、深度、修饰与信息的关系。未实际做眼动或记忆测试时不写实验结果，不编造量化评分。

完成状态使用“来源已登记／文字已核对／画面已核验／A—E 已分析／原则已同步”。流程是更新要求，不表示已有后台自动监控；新案例进入后需执行上述步骤。
