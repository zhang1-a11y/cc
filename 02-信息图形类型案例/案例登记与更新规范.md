# 案例登记与文档更新规范

## 一图一记录

在“案例”目录下以稳定 ID 建立案例 Markdown 文件与同名或相近名称的原图文件。文件名建议“C001-作品简称.md”；图片可放“案例/图像/C001-原图.png”。记录图像授权／来源、作者、发布时间（未知就写未知）、访问日期、图像尺寸与版本，不把无来源的转载图写成原作。若暂不能合法保存原图，记录可访问的来源链接与核对状态，不擅自拷贝。

每份记录至少包括：基本信息、原图／来源链接、可直接观察的元素与位置、数据结构与口径、统计图形和计算、点线面体符号色彩编码、数据／信息架构、视觉叙事路径、问题与反例、相关类型、相关 01 逻辑文档，以及“观察／解释／待核实”的证据等级。数值无法从图中读取时写“未见”，不可补造。引用画面局部时标明区域，如“左上图例”“第二行第三卡”。

## 每次新增案例的同步顺序

1. 新增原图或来源与案例记录，写清可核对的直接观察。
2. 在适用的 02 类型文档“案例索引”补具体案例链接；基于多案例对比提炼原则，并标明例外或适用条件。
3. 在适用的 01 数据逻辑文档开头或案例段落加**文本链接**，只链接 02 的案例记录，不复制图像；由案例修正 A–E 内容。
4. 更新 README 的案例证据状态及本次变更日期；检查相对路径、图片可用性、来源、术语和统计口径。

## 修订准则

把“在图中看到的事实”“分析者推断”“一般方法建议”分开。新的案例若冲突，先检查题材、统计单位和呈现目的，再写条件化原则，不用单例宣称普遍规律。保留案例 ID 以确保旧链接可用；替换原图要记版本和变更原因。每次案例合入都应同批修改对应方法文档，此为更新流程承诺；仓库不会在无人提交案例时自行产生分析。
