# 03 编目型信息图形概念定义

> 来源状态：已对照用户 PDF 第 10—13 页及第 40—71 页的方法文字。具体案例的构图、配色和数值尚待画面核验；以下通用方法与课件明示分别标注。来源与核验项目：[编目来源组](../02-信息图形类型案例/PDF对照与案例索引.md#catalog)。

## A 基本的数据逻辑

本质是**按共同属性归类的对象集合，以及描述这些对象的属性、标签和索引**：每条记录有稳定 ID、名称、描述、类别、多个可筛选属性与出处。核心问题是“有哪些、怎样找到与区分”，不要求时间先后、唯一父级或数量可加总。可按主题、用途、材质、状态等多维编目；一物多类时使用标签关系表，说明分类互斥与否，避免重复计数。

**课件对照**：第 2 页对应 Categorically，第 10 页使用 Cataloged Infographics；在本仓库沿用中文“编目型”，同时把“按标准归类”作为核心。分类解决同类归组，目录解决收录与检索；并非任意对象清单都具有清楚的分类逻辑。

**最小字段**：`item_id、name、category、attributes、sort_key、description、source`；多标签另存 `item_id ↔ tag_id`。先确定收录范围、分类依据和记录粒度，再比较对象，不能将产品、品牌、产地等不同粒度混在同一级计数。

## B 统计图形与计算

以清单、矩阵、卡片网格或分类索引为基础。若做频数图，先定义计数单位（对象数或标签出现次数）、分母和去重规则；多标签频数相加可能超过对象总数。可用条形图显示各类数量、点阵显示离散对象、二维矩阵显示交叉属性。排序依据可为名称、频数、用途或人为编辑顺序，必须说明；编目本身不要求统计图。

**计算示例（方法演示，非课件读数）**：一物多标签时，按对象 ID 去重得到总体 N；某类比例 = 该类不同对象数／N。若分母改用全部标签记录数，则结果表示标签份额，标题与图例必须随之改变。二维矩阵可用存在／不存在、频数或量值，三者不共用含混色标。

## C 视觉编码

卡片／点代表单个对象，分隔线与留白形成条目边界，面表示类别容器，稳定的符号标识对象类型；色彩按同一属性编码，不随页面任意变化。形状与图标可辅助检索，但使用相同大小时避免让读者误读为数量比例。缩略图统一裁切和背景，正文采用可扫描的标题—关键属性—说明层级；3D 物件示意不承担数值比较。长清单应提供文字标签，不能只依赖色块或图标。

## D 数据／信息架构

先规定纳入／排除边界、字段字典与缺失值，再建立分类导航、过滤条件、排序规则、条目详情与来源。推荐“总目录 → 类别入口 → 可扫描条目 → 单项详情”的结构。每项使用同一字段模板，允许字段为空但标注未知；索引和正文分离，使后续增加案例不会破坏原有 ID 与链接。

**架构落地**：类别表保存定义与纳入规则，对象表保存同字段事实，展示索引保存浏览顺序。遇到跨类对象用交叉标签或参见链接；只有存在真实包含关系时，才继续分成父子层级。

## E 视觉叙事架构

读者常按兴趣进入，不必强制从头读到尾。开头给出收录范围和选择路径，再用并列案例展示共性与差异，结尾提示尚未收录的边界。编辑可挑一个代表条目开篇，但不能以该条目代替整个类别的证据。

## 判别与更新

如果读者主要是在查找、浏览和比较条目，而不是阅读单向时间故事或树状包含关系，编目是主逻辑。新增案例后记录分类标准、字段一致性、导航可用性，并链接到对应案例。
