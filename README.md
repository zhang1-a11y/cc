# 信息图形方法与案例库

本仓库研究“数据如何组织”与“画面如何讲述”之间的关系。使用时先识别数据逻辑，再选择呈现类型；一张作品可以同时包含多种逻辑和多种表现方式。

## 目录

- [01-信息图形数据逻辑](01-信息图形数据逻辑/)：编年、层级、编目、字母表、地理五种组织逻辑。每篇按 A 数据逻辑、B 统计与计算、C 视觉编码、D 信息架构、E 视觉叙事架构撰写。
- [02-信息图形类型案例](02-信息图形类型案例/)：混合型、文字／列表型、时间轴型的表现方法，以及案例登记与更新规则。

## 两个维度

| 维度 | 要回答的问题 | 示例 |
| --- | --- | --- |
| 数据逻辑 | 数据之间究竟是什么关系？ | 事件的先后；父子层级；对象的归类；词条的字母索引；位置与空间邻接 |
| 呈现类型 | 读者通过什么画面阅读这些关系？ | 时间轴、文字列表、统计图与象形符号混合编排 |

“时间轴型”通常体现编年逻辑，但编年数据也能做小倍数图；“混合型”是表达方式，并不是与五种逻辑并列的第六种数据结构。字母表是检索顺序，不自动意味着数量大小。

## 案例证据状态

当前仓库尚未收到与本主题对应的案例原图和可核对的出处，因此现有内容是**方法定义与分析框架**，不把假设例子写成已经观察到的案例。案例加入后，应在 02 的案例记录里保留图像、来源、观察证据与分析；01 只添加指向相应案例记录的文本链接，不存放图片。

每次新增或修正案例，在同一次提交中同步更新相关 02 类型文档和 01 数据逻辑文档。详见[案例登记与更新规范](02-信息图形类型案例/案例登记与更新规范.md)。
